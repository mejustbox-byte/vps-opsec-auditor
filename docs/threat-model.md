# Модель угроз

## Активы и границы доверия
Активы: VPS/панель, аккаунт провайдера, DNS, токены, user-data, резервные копии,
каналы восстановления и свидетельства аудита. Границы: оператор → исполнитель →
недоверенная сеть; исполнитель → API провайдера; контрольная плоскость → metadata;
хранилище копий → стенд восстановления; частные сведения → обезличенный отчёт.
Любой ответ или импорт является недоверенным вводом.

| Угроза | Последствие | Контроль и предел доказательства |
| --- | --- | --- |
| Открытая панель/SSH | Захват доступа | Порты/панели/SSH и firewall IPv4/IPv6; без входа |
| IPv6 или непривязанный firewall | Обход правил | A/AAAA, привязки и эффективные правила |
| Кража токен API/аккаунта | Изменение VPS/DNS/backup | Минимальные права, срок, MFA, изолированное восстановление; MFA часто ручное |
| Секреты в cloud-init/metadata | Дальнейший захват | Обезличенные внутренние данные и отдельная лаборатория |
| Оставшийся DNS или неверный TLS | Перехват | Владение и цепочка; без регистрации чужого ресурса |
| Удаление backup с аккаунтом | Потеря восстановления | Изоляция, срок хранения, неизменяемость, измеренный restore |
| SSRF, смена адреса DNS между проверкой и подключением, redirect | Выход за область | Проверка каждого назначения, запрет переходов, бюджет |
| Вредоносная выгрузка/баннер | Инъекция/отказ в обслуживании | Размер, закрытая схема, безопасный вывод, без подстановки оболочки |
| Утечка через git/журнал/файлы CI | Публичный секрет | Синтетика, минимизация, ручное ревью и gitleaks перед push |
| Устаревшее/частичное свидетельство | Ложная уверенность | Время/источник/confidence, unknown/not_run, пропуски охвата |

## Допущения и исключения
Оператор подтверждает владение целями. API/экспорт не являются полной истиной;
скомпрометированная контрольная плоскость может лгать. Укрепление ядра, локальное
повышение прав, поиск вредоносного ПО, нагрузочный DDoS, эксплуатация и социальная
инженерия не охватываются. Аудитор не гарантирует защиту после момента наблюдения.
Критические цепочки: захват аккаунта → удаление backup; обход IPv6 → панель;
SSRF аудитора → metadata учётные данные. Для будущих сборщиков нужны отрицательные стенды.

## Защита автономного MVP
Сети/API/shell внутри CLI нет; SSRF/rebinding в текущем продукте невозможны.
Вход: обычный файл до 1 МиБ, закрытая схема, ограниченные псевдонимы/источники/время.
Повторные ключи, NaN и приведение неверных типов запрещены. Новые файлы создаются
с 0600 без перезаписи; диагностика не повторяет содержимое ввода и аргументов.
Отсутствие сети и защита файлов проверены тестами. Ложные свидетельства остаются
угрозой: источник/synthetic flag не аутентифицируют происхождение, ложь может дать pass.
Псевдонимы также чувствительны: реальные отчёты не публикуются. Скомпрометированный
локальный пользователь, интерпретатор или диск остаются за границами защиты.
