# Требования

## Цель и пользователи
Владелец VPS получает воспроизводимый отчёт о внешней поверхности и защите аккаунта
провайдера со свидетельствами, ограничениями и рекомендациями без изменения ресурсов.
Приоритет: внешняя поверхность, контрольная плоскость, восстановление.

## Целевой охват
- R01: явно разрешённые сетевые цели, IPv4/IPv6, публичные TCP-порты и панели.
  Неизвестный сервис не считается безопасным.
- R02: доступность SSH, host key/алгоритмы; политика password/root только по
  обезличенному разрешённому свидетельству, не по баннеру.
- R03: привязки облачный firewall, эффективный входящий/исходящий трафик, порядок правил,
  IPv4/IPv6, запрет по умолчанию и расхождения с наблюдениями.
- R04: IAM, владельцы/роли, минимальные права, область/срок/ротация токены API,
  MFA и каналы восстановления. Содержимое токенов не собирается.
- R05: cloud-init/user-data без секретов по обезличенным данным; защита metadata.
  Внешний запрос не доказывает защиту внутри гостевой системы.
- R06: DNS A/AAAA/CNAME, оставшиеся без ресурса записи, SAN/срок/цепочка TLS,
  протоколы и владение. Захват ресурса не предпринимается.
- R07: расписание, хранение, шифрование, изоляция и неизменяемость backup,
  свидетельство восстановления и измеренные RPO/RTO.
- R08: JSON/Markdown с check_id, псевдонимом, временем, источником, severity,
  confidence, status, remediation и причиной отсутствия сведений.
- R09: автономность по умолчанию; будущая сеть только для явно выбранного стенда.
- R10: явные возможности провайдера; недоступный API MFA/restore требует ручного
  подтверждения или unknown, а не pass.

## Контракт безопасности
Только чтение: запрещены изменение firewall/IAM/DNS, создание ресурсов, эксплуатация,
перебор, попытки входа, команды через SSH и автоматическое исправление.
Будущие запросы чтения могут попасть в журналы/ограничения частоты, что отражается
в отчёте. Нет массового поиска, произвольных адресов или автоматических redirect.
Будущие сборщики требуют списка адресов/портов и владельца, повторной проверки DNS,
запрета расширять область через CNAME/redirect, ограничений времени/параллельности,
бюджета и отмены. Link-local/metadata — только специально изолированная лаборатория.

Никаких реальных IP, ключей, токенов, исходных выгрузок, user-data или персональных
данных в git и CI. Только псевдонимы и документационные диапазоны. Частные данные
хранятся отдельно с минимизацией, сроком хранения и контролем доступа владельца.

## Реализованный MVP и приёмка
Автономный CLI частично покрывает R01–R07 через обезличенные типизированные факты,
выполняет R08/R09 и показывает недоступные источники для R10. Сбор данных, вычисление
эффективного firewall из исходные выгрузки и реальные проверки провайдера не реализованы.
Логические утверждения подтверждает владелец. Исходящий трафик, порядок firewall rules,
точные сроки токены API, детали TLS chain и полный DNS inventory не анализируются:
они остаются частными свидетельствами для обоснования переданных фактов.

Статусы: pass/fail/unknown/not_run. Пропуск, устаревание, unsupported/error → unknown;
нет сбора или явный not_run → not_run. Известный небезопасный факт → fail даже при
неполноте. not_applicable не предусмотрен: исключённая проверка остаётся not_run,
чтобы охват был виден. Будущее время → unknown. Для каждого правила проверяются
положительные/отрицательные/неполные/устаревшие/неподдерживаемые/ошибочные случаи,
пороги, CLI, установка и некорректный ввод. RPO/RTO и пороги задаёт владелец.
Синтетический pass не подтверждает реальную инфраструктуру.

Все документы и пользовательские пояснения на русском; команды, пути, ключи JSON,
статусы и ID сохраняются. Предварительный выпуск разрешён после доступных тестов/CI;
стабильный требует реального разрешённого стенда. Commit/push/PR/merge/release
разрешены; произвольные сканирования, реальные учётные данные и платные ресурсы запрещены.
