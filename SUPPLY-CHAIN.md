# Цепочка поставок и лицензии

## Инвентаризация
| Компонент | Роль | Лицензия/закрепление |
| --- | --- | --- |
| vps-opsec-auditor | Продукт | MIT; полный LICENSE и LICENSE.ru.md в пакетах |
| Python/stdlib | Окружение | PSF; Python >=3.12, проверен 3.12.14 локально |
| setuptools 80.9.0 | Только сборка | MIT; wheel SHA256 в requirements-build.txt |
| gitleaks 8.24.3 | Проверка секретов CI | MIT; SHA256 архива проверяется перед запуском |
| GitHub Actions checkout/setup-python/upload-artifact/download-artifact | CI и выпуск | MIT; полные commit SHA в workflows |

Сторонних runtime-зависимостей нет. Эта таблица — проверяемая инвентаризация текущего
набора, а не полный автоматически сформированный SBOM всех транзитивных инструментов
runner. При добавлении зависимости изучить её реальные license/notice и транзитивный
набор, записать точную версию/хеш и обновить инвентаризацию до слияния.

## Контроли поставки
Pip устанавливает setuptools с --require-hashes; продукт — --no-build-isolation
--no-deps. TLS/подписи/хеши не отключаются. Actions закреплены SHA, checkout не сохраняет
credentials. Сборка не имеет write-права; только publish использует штатный GITHUB_TOKEN
с contents:write для существующего draft. Никаких новых пользовательских токенов.
Gitleaks и check_public_data плюс ручное ревью не гарантируют обнаружение всех секретов.

## Целостность выпуска
Tag на проверенном main не передвигается. Строится именно commit tag; повторная
сборка проверяется хешами, wheel — чистой установкой. Публичные wheel/source/SHA256SUMS
скачиваются после публикации, сравниваются с проверенной сборкой. SHA256 обнаруживает
повреждение, но не удостоверяет издателя: доверенный GitHub-канал остаётся предпосылкой.
Подпись пакета/attestation/SBOM пока не реализованы. LICENSE и русское пояснение
проверяются внутри wheel и исходного архива. [Контроль](RELEASE-CHECKLIST.md).
