# Архитектура

## Назначение и границы
Продукт оценивает уже собранные обезличенные факты о внешней поверхности VPS и
контрольной плоскости провайдера. Это автономный MVP: нет сети, HTTP API, SDK,
базы данных, демона, исполнения команд SSH или исправления инфраструктуры.

## Реальные компоненты и поток
1. `cli.read_input(path)` открывает обычный файл с O_NONBLOCK и ограничивает чтение
   1 МиБ + 1 байт для обнаружения превышения. FIFO/устройства не принимаются.
2. `validation.load(bytes)` читает JSON с запретом повторных ключей/NaN, применяет
   встроенную закрытую схему и проверяет согласованность synthetic/source/state.
3. `audit.audit(data, now)` обходит 10 RULES. Сначала проверяются источник/состояние
   и возраст, затем типизированные факты и пороги policy.
4. Отчёт получает summary и findings с evidence/reason/remediation. JSON использует
   русские пояснения и неизменные машинные ключи; Markdown — русские подписи.
5. `cli.write_output(path, content)` создаёт новый частный файл через O_EXCL с 0600.
   При отсутствии --output отчёт попадает в stdout.

Пропуск сборщика — not_run; неизвестность/устаревание/ошибка — unknown; известное
небезопасное утверждение — fail даже при неполноте; pass требует всех применимых фактов.
Доказательство истинности утверждений владельца не реализовано.

## Расширение и остаточные ограничения
Сборщик должен оставаться отдельным компонентом с собственной моделью угроз,
разрешённой областью, лимитами и лабораторией. Rules не должны открывать сеть.
Новая схема требует синхронного обновления публичной и встроенной копий, примеров,
тестов и [контракта](CORE-CONTRACT.md). Новый адаптер не получает автоматически право
создавать ресурсы или выполнять restore. Подробный исходный разбор сохранён в
[docs/architecture.md](docs/architecture.md); угрозы — [THREAT-MODEL](THREAT-MODEL.md).
